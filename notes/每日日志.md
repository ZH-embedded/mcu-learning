  - `remove` 循环里写 `prev->next = cur`（要的是 `prev = cur`），第一轮 `prev == cur == head` → `head->next = head`，也是自环；而且 `prev` 初始成 `l->head`，删头时根本没有前驱可改
  - `remove` 删头结点没有单独分支，`free` 之后 `l->head` 成了野指针
  - `destroy` 一次写对（先存 `next` 再 `free`，循环后 `head = NULL`、`count = 0`）；`l->count--` 与最后的归零是两套记账，冗余但无害
- 学到：
  - 多文件编译：`.h` 只放声明、`.c` 放实现，**两个 `.c` 都要进命令行**；只编一个必然 undefined reference。`undefined reference` 永远发生在**链接期**，编译器把每个文件都编过了
  - `prev->next = cur` 和 `prev = cur` 差一个 `->`：一个是**改链表结构**，一个是**移动指针变量**。链表的连接本来就在，不需要每轮重建，只在摘掉结点那一刻改一次
  - `prev` 初始必须是 `NULL`：它是「`cur` 是头结点」的标记位。`prev` 从 `l->head` 起步就永远慢不了半步，删头无处下手
  - `free()` 只接受堆地址。`free(l)` 释放容器 ≠ 释放结点；栈地址交给 `free` 直接 abort。若容器真是 malloc 的，则变成 use-after-free，在几百行外炸
  - 单链表删除的本质是**改前驱的 `next`**，所以搜索时必须同时握着 `cur` 和前驱；头结点没有前驱，只能单独改 `l->head`
  - 输出参数 / 指针字段的区别：`p->next = x` 改的是**堆上的数据**，`p = x` 改的是**栈上的局部变量**。链表题一半的 bug 都是这两者写串了
- 今天最值钱的一条：**空表、空指针、首元素这三条边界路径，占了链表 bug 的大半**。`push_back` 和 `remove` 各错一处，两处都在「空表」这条路上；而且失败形态是**卡死**不是崩溃——没有报错、没有退出码、只有「程序不动了」。板子上就是这个现象：初始化之后 LED 不闪，你以为是时钟配错了
- 测试测不到的：**内存泄漏**。42 条断言只证明「结果对」，证明不了「每个 `malloc` 都恰好 `free` 一次」。`destroy` 是全链路最需要工具验证的一环，桌面上用 Dr. Memory 或 ASan 扫一遍
