# 素材与产出管理规范

> 目的：12-20 写简历、12 月底录演示视频时，能**在 5 分钟内**找到任何一天的证据。
> 代价：每天收工时多花 10 分钟。这 10 分钟是全篇性价比最高的投入。

## 一、三类东西，三种去处

| 类型 | 例子 | 放哪 | 进 Git 吗 |
|---|---|---|---|
| **代码** | C 练习、STM32 工程、RTOS demo | `01-c/` `02-stm32/` `03-rtos/` `04-comm/` | ✅ 进，每天提交 |
| **文字记录** | 故障记录、每日日志、知识点卡片 | `notes/` | ✅ 进（纯文本，diff 有意义） |
| **过程截图** | 每天的调试截图、波形图、报错截图 | `_shots/年-月/` | ❌ 不进，`.gitignore` 已屏蔽 |
| **精选证据** | 环境 5 张图、板子引脚图、每个项目的成品截图 | `_setup/`、各项目目录 | ✅ 进，README 里引用 |

**判断标准一句话**：*面试官会点开看的* 进 Git；*只给未来的自己看的* 进 `_shots`。

## 二、目录结构

```
mcu-learning/
├── README.md              进度 + 板子引脚表（仓库门面）
├── 01-c/                  C 练习，一周一个子目录
│   └── w0-hello/
├── 02-stm32/              一个工程一个目录，名字带日期
│   └── 2026-11-17-gpio-led/
├── 03-rtos/
├── 04-comm/
├── notes/
│   ├── 故障记录.md        模板已建好，只能当天写
│   └── 每日日志.md        每天一行，卡点必写
├── _setup/                环境截图 + 引脚图（进 Git）
└── _shots/                每日过程截图（不进 Git）
    └── 2026-10/
```

STM32 工程目录名统一 `日期-外设`，比如 `2026-11-17-gpio-led`、`2026-11-19-uart-printf`。好处是文件列表天然按时间排序，一眼看出进度，面试官也能看出节奏。

## 三、截图命名

```
2026-10-29_01-gcc.png
2026-10-29_02-ide-build.png
2026-11-17_uart-waveform.png
```

规则：`日期_序号-主题.png`。序号两位，同一任务内递增。**不要用 `截图1.png`、`新建文件夹`**——三天后你自己都认不出来。

## 四、每天收工的 10 分钟（固定四步）

1. **截图归档**：当天的图全丢进 `_shots/2026-10/`（按月分，避免单目录上千张）
2. **故障记录**：踩了坑就追加一条（现象/复现/定位/根因/修复/避免）——**当天不写，事后编不出来**
3. **每日日志**：两行就够 —— 今天做了什么 / 明天第一件事
4. **提交**：

```bash
cd /d/mcu-learning
git add .
git commit -m "d03: 串口 printf 重定向跑通"
git push
```

commit message 用 `dXX:` 开头（第几天），或 `wX-dX:`（第几周第几天）。连续 90 天有提交，本身就是简历上那句"GitHub 可查 commit 记录"的底气。

## 五、每个项目目录里的最小形态

12 月要"能演示"，指的是一个目录里同时有这四样：

```
2026-12-05-env-monitor/
├── README.md          问题 → 方案 → 硬件框图 → 关键截图 → 怎么验证
├── Core/ Inc/ ...     代码（CubeIDE 工程本体）
├── docs/              原理图截图、时序分析、测试数据
└── demo.mp4 链接      视频放 B 站/网盘，README 里贴链接，别把 mp4 塞进 Git
```

**大文件（视频、示波器原始数据）一律不进 Git**，放网盘/B 站，README 里贴链接。

## 六、每周日 10 分钟复盘

- 把这周 `_shots` 里最关键的 2–3 张，复制到对应项目目录并写进 README
- 检查：这周有几天没提交？没提交的那天，说明那天没动手
