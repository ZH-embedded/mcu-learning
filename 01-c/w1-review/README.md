## 为什么缓冲日挑这两题

它们的形状完全相反，正好互补：

| | 反转 | 合并 |
|---|---|---|
| 处理的链 | **一条** | **两条** |
| 难点 | 改指针的顺序（先存后改） | 结果链的挂载点（哨兵 / 二级指针） |
| 一个变量够不够 | 不够，要 `prev / cur / next` 三个 | 够，`tail` 一个就够（哨兵替它兜住了表头） |
| 最容易被忽略的 | 表尾的 `next` 要置 NULL | 一条走完后剩下的那段整段接上 |

再加上第 1 周已经写过的 `list.c`（增删查），这三块凑齐，链条类的手写题基本就覆盖全了。

## 白纸手写的正确流程

不是上来就写代码。**四步，缺一步都会在面试现场卡住**：

1. **画图**：三四个节点，标上地址 `0x100 / 0x200 / 0x300`。反转就在图上把箭头一根根掰过来，合并就在图上挑小的那个往新链上挂。
2. **说边界**：空表怎么办？只有一个节点怎么办？`a` 空 `b` 不空怎么办？——**先说出来，再写代码**。面试官这一条给的分比代码本身还多。
3. **写代码**：闭着眼睛写，不查任何东西。
4. **空跑一遍**：拿刚才画的那张图，人肉执行每一条语句，手指着节点走。这一步能抓掉九成的错。

上机编译是**最后一步**，而且只用来验证，不用来调试。**在纸上写不出来、靠编译器报错才改对的题，等于不会。**

## 测试在防什么

每题都留了完整的测试，你的任务是把函数体写出来，不是改测试。但这些断言各自在防哪个错，值得先看一眼：

**p01**

| 断言 | 防的错误 |
|---|---|
| 单节点 `next` 为 NULL | 写成 `prev = head; head->next = prev;` → 自环 |
| 四节点「仍是 4 个节点」 | 表尾没断干净 → `collect` 撞到上限，返回 16 而不是 4 |
| 新表头 == 原来的表尾 | 图省事用 malloc 新节点头插 → 序列对，但地址全变了 |
| 反两次回原样 | —— 这是**弱判据**，「什么都不做」也能过（上周 `reverse_bits8` 就栽在这），所以只当补充 |

**p02**

| 断言 | 防的错误 |
|---|---|
| `merge(a, NULL)` 返回 `a` 本身 | 重新 malloc 一份 → 序列对，指针不等 |
| 每个原节点都用了且只用了一次 | 接的时候复制了节点，或者某段被跳过 |
| `b` 的第一个比 `a` 表头小 | 哨兵版的 `tail` 忘了跟着走 → 新节点互相覆盖，最后只剩一个 |
| 等值取 `a` 在前 | 比较写成 `<` 而不是 `<=`（本题约定 `<=`，见函数注释） |

p02 里那个 `merge_two_lists` 如果写成 `return &dummy;`，编译时 `-Wall` 会直接报：

```
warning: function returns address of local variable [-Wreturn-local-addr]
```

这条警告**一定要当真** —— 它是本周唯一一个「编译器能替你看出来的悬垂指针」。

## 递归版的代价，量一次就知道

p01 最后两条断言用 500 个节点跑递归版，在 PC 上轻松过。但这个数字在板子上是另一个故事：

| 平台 | 栈 | 500 个节点（每帧约 48 字节） |
|---|---|---|
| x86-64 PC | 8 MB | 约 24 KB，占 0.3% |
| STM32F103（默认启动文件） | **1 KB** | 需要 24 KB —— **溢出 24 倍** |

栈溢出在 MCU 上不会给你一个漂亮的报错，它会**悄悄改写堆或全局变量**，然后在一个完全无关的地方 HardFault。所以：

- 面试答递归版，是为了说明「我懂递归怎么写」
- 工程里写迭代版，是为了说明「我知道这行代码跑在哪」

这两句话能同时说出来，比只会其中一个强得多。

## 面试时被追问的三个问题

**Q：为什么反转要三个指针，两个不行？**
不行。改 `cur->next` 的那一刻，`cur` 原来的后继就**永久丢失**了 —— 单链表没有反向指针，丢了就找不回来。所以必须有一个变量在改之前把后继存下来。第三个指针 `prev` 存的是「已经反转好的那段的头」，它每轮都要更新，也必须有独立变量。

**Q：合并为什么用哨兵节点？**
为了让「第一个节点挂在哪儿」和「后面的节点挂在哪儿」用同一句代码。不用哨兵的话，第一个节点得单独判断一次 `if (head == NULL) head = 谁; else tail->next = 谁;`，这个特判是最容易漏 `tail` 更新的地方。代价是多一个节点的栈空间（12 字节左右，用完就丢），换掉一个分支，非常划算。

**Q：合并能不能不破坏原链表？**
能，但代价很大：要么 malloc 新节点复制（O(n) 额外内存），要么写一条新链指向原节点（还是 O(n)）。链表合并的常规答案是**破坏性**的 —— 因为它本来就是个「重排指针」的操作，不破坏就没法 O(1) 空间。这一点要说清楚，否则面试官会以为你不知道自己在改别人的数据结构。
