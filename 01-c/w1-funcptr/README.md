## 今天真正要拿下的 6 个认知

**① 函数名在表达式里就是函数的入口地址**

```c
int add(int a, int b);

int (*f)(int, int) = add;    /* 不用写 &add，写了也一样 */
f(3, 4);                     /* ≡ (*f)(3,4) ≡ (**f)(3,4) */
```

三种调用写法编译出来一模一样。**"函数可以像变量一样被存起来"** 是今天所有东西的地基——
不能把函数当值传来传去，就没有回调、没有命令表、没有驱动里那一堆 `_Callback`。

**② 声明怎么读：`int (*f)(int)` 和 `int *f(int)` 差一对括号**

| 写法 | 是什么 | 怎么读 |
|---|---|---|
| `int (*f)(int)` | **函数指针**：变量，指向"收 int 返回 int"的函数 | 括号先把 `*` 和 `f` 绑在一起 → `f` 是指针 |
| `int *f(int)` | **函数**：收 int，返回 `int*` | 没有括号，`*` 先跟返回类型走 → 返回指针 |

`int (*f)(int)` 太绕，所以真实代码都用 typedef：

```c
typedef int (*binop_t)(int, int);   /* 之后写 binop_t，不用再写那串括号 */
```

**③ 回调 = 骨架固定，动作可换**

```c
void for_each(int *arr, int n, void (*fn)(int *));
```

`for_each` 里的循环只写一次；传 `fn` 就变成"每个元素加一"，传别的就变成"每个元素打印"。
**函数体里从头到尾不出现任何具体动作** —— 想知道它干了什么，只能看调用者传了谁。

嵌入式里全是这个形状：`HAL_GPIO_EXTI_Callback()`、`xTaskCreate(..., task, ...)`、
`qsort(arr, n, size, cmp)`。今天你觉得它抽象，12 月你会发现没有它寸步难行。

**④ 函数指针数组 = 命令注册表（今天的硬产出）**

```c
typedef struct {
    const char *name;
    void (*handler)(void);
    const char *help;
} cmd_entry_t;

static const cmd_entry_t MENU[] = {
    { "led on",  cmd_led_on,  "点亮 LED" },
    { "led off", cmd_led_off, "熄灭 LED" },
    { "status",  cmd_status,  "打印状态" },
};
```

没有它，命令分发就是一长串 `if (!strcmp(...))`，加一条命令要改三个地方（函数、if 链、帮助文本），
改漏一处就是 bug。有了它，**加命令 = 往数组里加一行**，查找、执行、帮助全自动跟上。

长度用 `sizeof(MENU)/sizeof(MENU[0])` 算，加行不用改。真实代码里这东西叫
命令表 / 分发表 / ops 结构体，RTOS 的 shell、AT 指令、UART 协议码全在用。

**⑤ `const` 与指针的三种组合：看 const 在星号哪边**

| 写法 | 锁什么 | 能改 `*p`？ | 能改 `p` 自己的指向？ |
|---|---|---|---|
| `const int *p` | 内容 | ❌ | ✅ |
| `int *const p` | 指针（必须初始化） | ✅ | ❌ |
| `const int *const p` | 两个都锁 | ❌ | ❌ |

一句话：**const 在星号左边锁内容，在星号右边锁指针**。
`const` 是纯编译期的，运行时不存在、不占内存、编译出来和没写一样（`p03` 里有 `_Static_assert` 证明）。
实用结论只有一条：**函数的指针形参只要不打算改它指向的内容，就加 `const`**。

**⑥ 结构体形参只该有两种写法**

```c
void f(const sensor_t *s);   /* 只读 */
void f(sensor_t *s);         /* 要改 */
```

因为 `void f(sensor_t s)` 是**整块拷贝**：16 字节的结构体，传 10 个就是 160 字节压到栈上，
而板子的栈只有几 KB。更坑的是函数里改的是副本，外面一点没变 —— `p06` 第 3 题。
（`->` 就是 `(*p).` 的语法糖，`(*p).id` 的括号不能省，`*p.id` 是 `*(p.id)`，编译直接报错。）

**⑦ 回调要改外部状态，靠 `void *ctx`，不靠全局**

```c
typedef void (*visit_fn)(int value, void *ctx);
void walk_with_ctx(const int *arr, int n, visit_fn fn, void *ctx);
```

回调签名里加一个 `void *`，调用者把自己的东西塞进去。用全局变量也能"跑通"，但立刻出三个问题：
两处同时累加会串、回调只能服务一个累加器、测试之间互相污染。
POSIX 的 `pthread_create(..., void *arg)`、FreeRTOS 的 `xTaskCreate(..., pvParameters)`、
各种 `xxx_Callback(void *user)` 里那个 `void *` 就是干这个的。
