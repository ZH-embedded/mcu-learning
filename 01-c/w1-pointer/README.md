## 今天真正要拿下的 6 个认知

比写完 6 个程序值钱，12 月写驱动时会直接撞上：

**① `arr[i]` 就是 `*(arr + i)`，两者编译出来一模一样**

```c
arr[i]  ≡  *(arr + i)  ≡  *(p + i)   /* p = arr */
```

理解了这条，`p03` 那三种遍历写法就不是三种写法，是同一种。**看 HAL 库源码全靠它**——`GPIOA->ODR |= (1u << n)`，`GPIOA` 本身就是一个指向结构体的指针。

**② 数组名不是指针变量，不能自增**

```c
arr++;              /* ❌ 编译错误：arr 是数组名，不是可修改的左值 */
int *p = arr; p++;  /* ✅ 把首地址拷进指针变量再动 */
```

**③ 指针变量本身占 8 字节，跟它指向什么无关**

```c
sizeof(int *)   == 8     /* 64 位机器 */
sizeof(char *)  == 8     /* 也是 8 */
sizeof(int)     == 4
```

指针存的是地址，地址长度由机器决定，不由指向的类型决定。板子是 32 位，`sizeof(int *)` 就是 **4**——这是跨平台时最容易算错的一个数。

**④ `int *p[3]` 和 `int (*p)[3]` 差一个括号，意思完全不同**

| 写法 | 是什么 | `sizeof` | 怎么读 |
|---|---|---|---|
| `int *p[3]` | **指针数组**：3 个 `int*` 组成的数组 | 24（3×8） | 先看右边 `[3]`，所以是数组 |
| `int (*p)[3]` | **数组指针**：指向"3 个 int 的数组" | 8（指针） | 括号先跟 `*`，所以是指针；`sizeof(*p)` 才是 12 |

一句话记法：**无括号先跟数组走，有括号先跟星号走。**

为什么会写晕：`int (*p)[3]` 里的 `*p` **就是那个数组本身**，所以 `(*p)[0]` 才是第一个 int，而 `p[0]` 是"整个 `int[3]`"。

**⑤ 二级指针的用途只有一个：改调用者的指针变量**

```c
void f(int  *p)   /* 能改 *p，不能改 p 自己指向哪 */
void f(int **p)   /* 能改 *p，也就是能改调用者的指针 */
```

12 月链表删除**头节点**就是靠这个：头节点被删时，head 本身要变，而函数参数是值传递，只能传 `&head`。
今天 `p04_second.c` 的 `point_to` / `take_and_clear` 就是这个模式的预热。

**⑥ 函数参数里的数组会"退化"成指针，`sizeof` 在那里失效**

```c
void f(int a[10]) { printf("%zu\n", sizeof(a)); }   /* 打印 8，不是 40！ */
int  count(int arr[]) { return sizeof(arr)/sizeof(arr[0]); }   /* 永远得到 2 */
```

所以**长度必须单独传一个参数**。这是 `p06_bug.c` 第 4 题。
今天是 PC 上看到个错数字，板子上就是越界读写、HardFault、莫名其妙跑飞。
