## 四道题的顺序是有讲究的

**p01 → p02** 是同一个功能的两种实现。函数版先写，写完你会有个疑问：位号明明是常量，为什么汇编里还要算？因为函数拿到的永远是运行时参数。换成宏之后，位号在调用点展开成常量，编译器直接生成立即数指令。**这就是寄存器操作全部用宏、不用函数的原因** —— 不是为了好看，是为了让编译器看见常量。

**p02 的括号部分是今天的重点。** 你自己写的宏，`REG_SET(r, 7 & 3)` 是对的，`BAD_SET(r, 7 & 3)` 会把这一位吃掉。宏展开是**文本替换**，不是函数调用，优先级问题全在展开后重新解析。

**p03** 从「一位」升到「一段」。真实外设寄存器不是一位一个功能，而是 `bit0-3 分频 / bit4-11 比较值 / bit12-15 模式`。读写字段三步走，最容易被忘的是**清旧值**：少了它，先写 `0xF` 再写 `0x3`，寄存器里是 `0xF`。

**p04** 是四个能直接进面试的技巧，共同点是不用循环 32 次（除了位序反转）。注意 `reverse_bits8` 的测试里我避开了 `0xA5` —— 它是 8 位回文，反转后还是自己，拿它当样例的话，写成「原样返回」也能全绿。

## 宏的四条纪律

1. **每个参数都加括号**：`(reg)` `(bit)`。理由见 p02 的 `BAD_SET` 用例，`&` 的优先级比 `<<` 低，括号一少整条表达式就被拆成两半
2. **整体再加一层括号**：宏是表达式，参与 `a = REG_GET(...) + b` 这种更大表达式时不能被拆散
3. **常数写 `1u`**：`1 << 31` 在 32 位 `int` 上是未定义行为（结果放不进 `int`）。这一条是本周验收里「第 31 位」的直接原因
4. **宏名和左括号之间不能有空格**：`#define M (x)` 是对象式宏，不是函数式宏

另外两条不属于括号、但同样致命：

- **参数不要有副作用**：`REG_GET(r, i++)` 里 `bit` 只出现一次还算安全，但 `#define MIN(a,b) ((a)<(b)?(a):(b))` 里 `i++` 会自增两次。规矩是「宏参数传变量，别传表达式」
- **寄存器必须 `volatile`**：否则编译器看到「写了没人读」就可能把读-改-写整条优化掉。桌面上看不出来，上了板子就是「配置寄存器没生效」

## 多位字段的三步法

```c
mask = ((1u << width) - 1u) << pos;     /* 1. 造掩码 */
*reg  = (*reg & ~mask) | ((val & bits) << pos);
/*             2. 清旧值      3. 写新值（先截断再移位） */
```

三个边界必须处理，否则就是静默错误：

- `width == 32` 时 `1u << 32` 是 UB，要单独走 `0xFFFFFFFFu`
- `val` 超宽要先 `& bits` 截断再移位，否则 `0xFF << 28` 溢出 32 位
- `pos + width > 32` 直接拒绝，不能「写进去一半」

## 认知清单（做完再看）

**位操作**

- 置位 `|=`、清位 `&= ~`、翻转 `^=`、取位 `(x >> n) & 1u`。四个动作里只有「取位」不加 `1u` 也能跑，但统一写 `1u` 最省心
- `x & -x` 保留最低位的那个 1，其余清零。用途是遍历集合里的元素
- `x & (x - 1)` 清掉最低位的那个 1。循环次数 = 1 的个数，这就是 Brian Kernighan 的 popcount
- 判断 2 的幂：`v != 0 && (v & (v - 1)) == 0`。**外层括号不能少**，`&` 的优先级比 `==` 低，少一层就变成 `v & ((v-1) == 0)`
- 无符号的 `0u - v` 是定义良好的回绕；有符号的 `-v` 在 `INT_MIN` 上是 UB。位技巧全部在无符号上做

**寄存器**

- 宏比函数快的真正原因不是「没有函数调用」，而是**位号能在编译期折叠**
- `1u << 31` 合法，`1 << 31` 是 UB。第 31 位是所有移位 bug 的集中地
- 寄存器的读-改-写必须 `volatile`，否则优化器有权把它删掉
- 位域做寄存器映射看着很美，但位序和布局都是实现定义的。真要可移植，就退回 `REG_SET` 宏
