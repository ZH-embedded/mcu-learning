## 今天真正要拿下的 5 个认知

这五条比写完 6 个程序值钱，都是 11 月写驱动时会直接撞上的：

**① 数组传参就退化成指针，`sizeof` 在函数里失效**

```c
void f(int a[10]) { printf("%zu\n", sizeof(a)); }   /* 打印 8，不是 40 */
```

函数参数里的 `int a[]` 和 `int *a` 完全等价。所以**数组长度必须另外传一个参数**——这就是 `bin_search(arr, n, target)` 要 `n` 的原因。12 月写环形缓冲区时，如果忘了传 `len`，`sizeof` 会给你一个漂亮但完全错误的答案。

**② 字符串是"以 `\0` 结尾的 char 数组"，`sizeof` 和 `strlen` 不是一回事**

```c
char s[] = "abc";
sizeof(s)  /* 4 —— 含结尾 \0，编译期算出 */
strlen(s)  /* 3 —— 不含 \0，运行期数到 \0 为止 */
char *p = "abc";
sizeof(p)  /* 8 —— 指针的大小！陷阱 */
```

还有一层：**UTF-8 下一个汉字占 3 字节**。`strlen("中文")` 是 6，不是 2——这决定了你以后处理串口收到的中文时，不能用"字符数"当缓冲区长度。

**③ 递归好看，但在 MCU 上是奢侈品**

每层递归都吃栈。STM32F103 的默认栈通常只有 1–2 KB（链接脚本里 `_Min_Stack_Size`），一个递归深度 1000 的函数就能把栈打穿，表现是 HardFault 或"莫名其妙跑飞"，而且**现象随机，极难定位**。

今天的递归题（汉诺塔/阶乘）在 PC 上随便写，但要知道这个界限：**嵌入式里超过 10 层的递归要想清楚，能用循环就用循环**。12-12 讲 HardFault 时会回到这里。

**④ 二分查找的两个经典 bug**

```c
int mid = (left + right) / 2;      /* ❌ 大数组时 left+right 溢出成负数 */
int mid = left + (right - left) / 2;  /* ✅ */
```

以及循环条件是 `left <= right` 还是 `<`——**取决于你把区间定义成闭区间 `[left, right]` 还是半开 `[left, right)`**。想清楚一个，另一个就不会错；想不清楚就会写出"某些元素永远找不到"的代码，测试还刚好不覆盖到。

**⑤ `strcmp` 只保证"符号"，不保证"差值"**

C 标准只说：相等返回 0，前者小返回负数，前者大返回正数。**没有规定必须是 -1/1**。所以永远写 `if (strcmp(a,b) == 0)` 或 `< 0`，不要写 `== -1`。glibc 和某些嵌入式库实现不一样，`== -1` 在 PC 上过、到板子上就挂。
