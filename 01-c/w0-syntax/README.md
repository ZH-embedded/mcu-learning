## 怎么组织

一人一文件，命名 `p01_temp.c` … `p15_diamond.c`；编译：

```bash
gcc p01_temp.c -o p01_temp.exe && ./p01_temp.exe
```

或者一次全编（在 `01-c/w0-syntax/` 下）：

```bash
for f in p*.c; do gcc "$f" -o "${f%.c}.exe" || echo "编译失败: $f"; done
```

## 15 题

### 类型与数值（1–5）

| # | 文件 | 要求 | 验收点 |
|---|---|---|---|
| 1 | `p01_temp.c` | 摄氏 → 华氏（`F = C*9/5 + 32`），输入 `-40`、`0`、`37`、`100` | 输出保留 1 位小数；**同一公式写三种顺序对比**：`C*9/5`、`9/5*C`、`9.0/5*C`，说出哪个错、错在哪一步；
| 2 | `p02_base.c` | 十进制 255 转 2 / 8 / 16 进制，**不许用 `%x` `%o`**，自己用 `/` 和 `%` 算 | 输出 `11111111` / `377` / `FF`；反过来再写一个 16 进制字符串转十进制 |
| 3 | `p03_bits.c` | 打印一个 `unsigned char` 的 8 个二进制位（从高位到低位），输入 0、1、0xA5、255 | 用 `>>` 和 `&1`；再写一个版本做「置位/清位/取反」第 n 位，打印前后对比 |
| 4 | `p04_sizeof.c` | 打印 `char/short/int/long/long long/float/double/指针` 的 `sizeof`，再用 `<limits.h>` `<float.h>` 打印 `INT_MAX`、`INT_MIN`、`UINT_MAX` | 亲手验证 `INT_MAX + 1` 溢出成负数（**先把预测写进注释，再跑**） |
| 5 | `p05_unsigned.c` | 验证三个反直觉现象：`unsigned` 减法下溢、`-1 < 0u` 为假、`sizeof` 返回无符号导致 `sizeof(int) - 5 > 0` 为真 | 每条先写预测再运行；能说出「编译器为什么这么干」 |

### 运算与格式（6–10）

| # | 文件 | 要求 | 验收点 |
|---|---|---|---|
| 6 | `p06_divmod.c` | 打印 `7/2`、`-7/2`、`7%2`、`-7%2`、`7/-2`、`-7%-2` | 负数取模的符号跟谁走？结论写进注释（面试问过） |
| 7 | `p07_float.c` | 验证 `0.1 + 0.2 == 0.3`、`0.1f + 0.2f == 0.3f`；用 `%.20f` 看真实值；比较 `float` 与 `double` 精度 | 能解释为什么不能直接用 `==` 比较浮点，以及 `fabs(a-b) < 1e-6` 的写法 |
| 8 | `p08_printf.c` | 同一组数据用不同格式打：宽度 `%8d`、左对齐 `%-8d|`、补零 `%08.2f`、`%x`、`%#x`、`%p`、`%%` | 能背出 `%5.2f` 里 5 和 2 各是什么；打印指针必须 `(void*)` 强转 |
| 9 | `p09_priority.c` | 故意写 6 个易错表达式：`a = b = c + 1`、`x & 1 == 0`、`i++ + ++i`、`a > b ? a : b > c ? b : c`、`1 << 2 + 3`、`a | b && c` | **每个先写预测值**再跑，错一个就在注释里写一行为什么（这题的价值全在预测） |
| 10 | `p10_typeconv.c` | 隐式转换链：`char → int → unsigned → long → float → double`，每步打印值和 `sizeof`；再做一次 `int` 转 `char` 截断（如 300 → ?） | 能说出「整型提升」和「截断」分别发生在什么时候 |

### 分支与循环（11–15）

| # | 文件 | 要求 | 验收点 |
|---|---|---|---|
| 11 | `p11_leap.c` | 闰年判断：能被 4 整除但不能被 100 整除，或能被 400 整除 | 测 1900（否）、2000（是）、2024（是）、2023（否）；把条件写成一行的版本和分层 if 的版本各一遍 |
