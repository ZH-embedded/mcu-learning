# ref —— 对照实现

这里放的是**另一种写法**，用来和你自己写的版本对比，不是标准答案。

目前有三个：

| 文件 | 对照的是 | 主要差别 |
|---|---|---|
| `p02_base_ref.c` | 根目录 `p02_base.c` | 你的版本三个函数各写一遍；这里合并成一个 `to_base(v, base, buf)`，并把结果拿回来对齐打印 |
| `p03_bits_ref.c` | 根目录 `p03_bits.c` | 你的版本在打印循环里改临时变量 `bit`（只改变显示，`c` 本身没变）；这里让 `c` 真的被修改，每步都打印当前值 |
| `p04_sizeof_ref.c` | 根目录 `p04_sizeof.c` | 你的版本已经和它基本一致（`%zu` + `%u` + 无符号加一），差别只在这里多了整型取值范围、`float`/`double` 精度和一个“操作了但值没变”的演示 |

**怎么看**：先跑自己的，再跑 ref 的，`diff` 输出和代码，找出“为什么另一种写法更短/更清楚”，而不是记住哪一种是对的。

> 代码没有唯一正确写法，只有“哪种更容易改、更容易查错”。这也是面试里问“你为什么这么写”时，你能答的东西。
