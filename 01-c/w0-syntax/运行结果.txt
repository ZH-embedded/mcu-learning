===================== p05_unsigned =====================
== 现象一：无符号减法下溢 ==
a = 0, b = 5
a - b          = 4294967291   （预期：一个巨大的数）
a - b > 0      = 1    （预期：真 —— 下溢之后当然是正数）
a - 1 > 100000 = 1    （预期：真）
  → 所以“够不够”要用 if (a >= b)，不能写 if (a - b >= 0)

== 现象二：有符号和无符号比较，负数会变巨大正数 ==
-1 <  1  = 1   （都是 int，正常比较）
-1 < 1u  = 0   （-1 被转成 4294967295，所以为假）
(unsigned)(-1) = 4294967295
  → 混合比较前先把无符号那侧和有符号那侧统一类型

== 现象三：sizeof 返回无符号，减法会下溢 ==
sizeof(int) = 4
sizeof(int) - 5       = 18446744073709551615   （2^64-1，本机 size_t 是 8 字节）
sizeof(int) - 5 > 0   = 1
(unsigned)(sizeof(int) - 5) = 4294967295
  → 下溢后的“巨大值”有多大，取决于类型宽度

== 附：无符号倒序循环 —— 嵌入式死循环头号成因 ==
  i = 3
  i = 2
  i = 1
  i = 0
  i = 4294967295
  i = 4294967294
  ... 停不下来：0 再减 1 回绕成 4294967295
  正确写法：for (i = n; i-- > 0; )  或  for (i = n; i > 0; i--)

===================== p06_divmod =====================
a      b      a/b      a%b      a == (a/b)*b + a%b ?
--------------------------------------------------------
7      2      3        1        成立
-7     2      -3       -1       成立
7      -2     -3       1        成立
-7     -2     3        -1       成立
1      2      0        1        成立
-1     2      0        -1       成立

结论：
1) 除法向 0 截断：-7/2 = -3（不是 -4，也不是 -3.5 取整到 -4）
2) 余数符号跟随被除数：-7%2 = -1，7%-2 = 1
3) 恒等式 a == (a/b)*b + a%b 永远成立，这是取模的定义

浮点除法对照：-7.0/2 = -3.50（这里才出现小数）

===================== p07_float =====================
== 一、看起来相等，实际不等 ==
0.1 + 0.2      = 0.30000000000000004441
0.3            = 0.29999999999999998890
0.1 + 0.2 - 0.3 = 5.55111512312578270212e-17
(a + b) == 0.3 = 0   ← 0 表示假
近似比较       = 1   ← 1 表示真（误差 < 1e-9）

== 二、float 比 double 更早出错 ==
0.1f          = 0.10000000149011611938
0.1f + 0.2f   = 0.30000001192092895508
(fa + fb) == 0.3f ? 1
sizeof(float) = 4, sizeof(double) = 8

== 三、有效数字：float 约 7 位，double 约 16 位 ==
float  1.0f/3.0f = 0.333333343267
double 1.0/3.0   = 0.3333333333333333

== 四、累加一万个 0.1 的漂移 ==
double 累加 = 1000.0000000002  （误差 1.588e-10）
float  累加 = 999.9028930664  （误差 9.711e-02）

结论：
1) 浮点数不能用 == 比较，用 |a-b| < eps
2) eps 要跟量级匹配：量级 1e6 时用 1e-6 做阈值等于没做
3) STM32F103 没有 FPU，float 比 double 快得多，统一用 float + f 后缀

===================== p09_priority =====================
1) a = b = c + 1     → a=4 b=4 表达式值=4
2) x & 1 == 0        → 0 （实际被解释成 x & (1==0)，恒为 0）
   正确写法 (x & 1) == 0 → 1
3) i++ + ++i          → 4 （UB，本机是它，别依赖）
4) a > b ? a : b > c ? b : c → 5
5) 1 << 2 + 3          → 32 （是 1<<5，不是 (1<<2)+3=7）
6) 4 | 0 && 3          → 1 （是 (4|0)&&3 = 1，不是 4|(0&&3) = 4）
7) *p++                → 100，之后 p 指向 200

记忆方法：
  括号 > 单目 > 算术 > 移位 > 关系 > 相等 > 位与 > 位异或 > 位或 > 逻辑与 > 逻辑或 > 三目 > 赋值 > 逗号
  实际工作中：拿不准就加括号，加括号不丢人，猜错优先级才会出事

===================== p10_typeconv =====================
== 一、整型提升：小于 int 的类型参与运算时先变成 int ==
unsigned char 200 + 100 = 300   （char 先提升成 int，所以不会在 8 位里回绕）
sizeof(c + 100) = 4   （结果是 int，不是 char）
强制截回 8 位：(unsigned char)(200 + 100) = 44   （300 - 256 = 44）

== 二、截断：大类型赋值给小类型，只保留低位 ==
int 300 -> char = 44   （300 = 0x12C，只留 0x2C = 44）
int -1 -> unsigned char = 255   （0xFFFFFFFF 只留 0xFF = 255）

== 三、有符号与无符号互转：位模式不变，解释变了 ==
unsigned 4294967295 -> int = -1
int -1 -> unsigned         = 4294967295
两者位模式都是 0xFFFFFFFF，只是最高位被解释成符号位或数值位

== 四、转浮点：int -> float 也可能丢精度 ==
int 16777217 -> float = 16777216.0   （float 尾数只有 24 位，末位被舍掉）
double 能精确表示：16777217.0

== 五、混合运算的转换顺序 ==
c + i = -10      （char 提升为 int）
i + u = 10      （int 转 unsigned，负数变巨大）
i + d = -18.50    （int 转 double）
sizeof(c+i)=4 sizeof(i+u)=4 sizeof(i+d)=8

规则：
1) 小于 int 的类型先提升为 int，再参与运算
2) int 与 unsigned int 混算，统一转成 unsigned（这就是 -1<1u 为假的原因）
3) 有浮点参与，统一转成浮点（float/double 中等级高的那个）
4) 赋值/传参时发生截断，多出的高位直接丢弃，不会有任何提示

===================== p15_loop =====================
== 一、同一件事写三遍：求 1..100 的和 ==
for      : 5050
while    : 5050
do-while : 5050

== 二、遇到第一个能被 7 整除的数就停（for + break）==
第一个：7

== 三、do-while 和 while 的关键差别 ==
while    ：条件一开始为假 → 循环体一次都没执行
do-while ：循环体执行了 1 次
           因为 do-while 先执行后判断

== 四、continue 陷阱：while 里忘记自增就是死循环 ==
错误写法（用 guard 保护，只演示 6 次）：
  卡在 i=0
  卡在 i=0
  卡在 i=0
  卡在 i=0
  卡在 i=0
  卡在 i=0
  ... 真实代码里会无限循环
正确写法：把自增放到 continue 之前，或者改用 for
  奇数：1
  奇数：3

选择规则：
1) 次数确定 → for；次数不确定但可能一次都不做 → while；至少做一次 → do-while
2) do-while 的典型场景：先采样再判断、菜单至少显示一次、重试逻辑
3) while + continue 时，自增一定要在 continue 之前，否则死循环
4) 任何循环都问一句：这个循环一定会结束吗？靠什么条件结束？
